# Settings extension

Mode: Operate. Seed key: incumbent-settings-extension (precisely scoped feature; no visual-world replacement).

## Direction contract

WORLD: Preserve the existing dark Electron island, system sans typography, restrained state colors and drawn SVG icons. Extend it into a normal focusable settings window.

FIRST VIEWPORT: Show automatic approval's master switch, permission and question rules, fallback selection, and the route to native Agent integration. Automation is the initial section; a stable sidebar connects general settings, integrations and recent decisions.

LAYOUT: Desktop sidebar with a readable, bounded form column; narrow browser preview becomes a compact top navigation. Native window minimum width is 640px. No modal or marketing composition.

INTERACTION: Switching automation changes the master status immediately after durable save. Tray and configuration share the same state. Pausing stops native replies. Hook installation/removal, errors, disabled controls, loading, history and empty states are real.

CONTENT: Chinese product labels. Distinguish logged sessions from connected native interaction channels. Claude HTTP hooks and Codex shared app-server are supported; unsupported clients stay manual. Browser preview is labeled. No approval or answer is called tool execution success.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance. No new shipping raster assets are used; screenshots are review evidence only.

## Quality bar

Preserve existing island behavior; provide an independent, keyboard-usable configuration window. Forms need linked labels/descriptions, visible focus, durable save feedback, and no horizontal overflow at desktop, 640px and 390px preview widths. Native smoke tests cover settings persistence, tray synchronization, Hook installation/removal, approvals, answers, pause and window lifecycle. Mechanical detector found no issues.

## Evidence and decisions

The user requested automatic permissions/recommended answers and a configuration UI beyond the tray. Optional questions about unsupported recommendations and preferred clients received no reply during implementation; manual fallback and verified native integrations were used, and fallback is configurable. No aesthetic change was requested. Screenshots live under .impeccable/review and are synthetic smoke-test state. No approved image comp exists for this code-led extension.
